# Security policy

## Supported versions

This is a documentation repository. Corrections are applied to the default branch; older snapshots are not maintained.

## Reporting a vulnerability

Do not open a public issue for a vulnerability, exposed secret, or report containing sensitive data. Use GitHub’s **Private vulnerability reporting** feature on the repository’s Security tab.

Include:

- affected document, example, workflow, or configuration;
- impact and realistic abuse path;
- minimal reproduction without real credentials or personal data;
- suggested mitigation, if available.

Maintainers should acknowledge a report within five business days and coordinate disclosure after triage. Timelines depend on severity and whether downstream users need time to adapt.

## Scope

Security reports may cover unsafe example code, misleading security guidance, CI workflow risks, dependency or action compromise, secret exposure, or repository configuration. General improvements belong in a normal issue.

Never test a report against systems or data you do not own or have permission to assess.
